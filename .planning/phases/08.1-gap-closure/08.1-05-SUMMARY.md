# Phase 8.1 Plan 05: CLI Consistency Fixes Summary

Fixed consistency issues across CLI applications: unified slot detection logic, removed hardcoded development paths, and added background monitor startup.

## One-Liner

WakeupNeo GetActiveSlots now uses ShaderExists (matching Bluepill); dev paths removed; Monitor starts from Bluepill.

## What Was Done

### Task 1: Fix WakeupNeo GetActiveSlots to use ShaderExists
- **Issue:** GetActiveSlots used color comparison (excludes default green slots)
- **Fix:** Changed to use `_shaderService.ShaderExists(k)` like Bluepill
- **Result:** Default green shader slots are now correctly included in restore

### Task 2: Remove hardcoded dev path from ShaderService
- **Issue:** `@"C:\Users\ehome\Documents\Matrix\shaders"` hardcoded
- **Fix:** Replaced with relative path fallback (parent directory check)
- **Result:** Clean deployment without user-specific paths

### Task 3: Start MatrixShader.Monitor from Bluepill
- **Issue:** PowerShell starts monitor for drag-snap; C# did not
- **Fix:** Added StartMonitorProcess() after successful session restore
- **Result:** Monitor starts hidden when available (silent failure if missing)
