  <action>
Modify the DrawLayer function in all Matrix shader files to use a high-frequency hash for column-specific phase offsets.

Current problematic code in DrawLayer (~line 62-66):
```hlsl
float col_rnd = random(float2(cell_id.x, seed_shift));
if (col_rnd > RAIN_DENSITY) return float3(0,0,0);
float final_speed = ((col_rnd * 0.5 + 0.2) * 10.0 * RAIN_SPEED * speed_mult) / depth;
float rain_pos = cell_id.y - (Time * final_speed) + (col_rnd * 1000.0);
float cycle = frac(rain_pos / grid_dims.y * 1.5);
```

Replace with:
```hlsl
float col_rnd = random(float2(cell_id.x, seed_shift));
if (col_rnd > RAIN_DENSITY) return float3(0,0,0);

// HIGH VARIATION: Use high-frequency hash for unique phase per column
// This prevents the "breathing" sync where all columns animate together
float col_hash = frac(sin(cell_id.x * 127.1 + seed_shift * 311.7) * 43758.5453);
float phase_offset = col_hash * grid_dims.y * 2.5;  // 2.5x screen height variation

float final_speed = ((col_rnd * 0.5 + 0.2) * 10.0 * RAIN_SPEED * speed_mult) / depth;
float rain_pos = cell_id.y - (Time * final_speed) + phase_offset;
float cycle = frac(rain_pos / grid_dims.y * 1.5);
```

Key changes:
1. Added `col_hash` using high-frequency sine hash (different from `col_rnd`)
2. `phase_offset` uses `col_hash * grid_dims.y * 2.5` for significant vertical offset
3. `rain_pos` uses `phase_offset` instead of `col_rnd * 1000.0`

The magic numbers:
- `127.1` and `311.7` are prime-like values that create high-frequency variation
- `43758.5453` is a standard hash multiplier
- `2.5` multiplier ensures enough vertical offset to break sync

Apply this same change to all 6 shader files (Matrix-1.hlsl through Matrix-6.hlsl).
