# Phase 10.5: Global Hotkeys - Context

**Gathered:** 2026-01-30
**Status:** Ready for planning

<domain>
## Phase Boundary

Port matrix_hotkeys.ps1 to C# — system-wide keyboard shortcuts that work when Matrix windows are minimized/unfocused. Hotkeys control layout, window swapping, shader parameters, and layer toggles.

</domain>

<decisions>
## Implementation Decisions

### Process Lifecycle
- Launches from Matrix entry points (bluepill, wakeupneo, redpill) — NOT on Windows login
- Single instance enforcement — new launch does nothing if already running
- Auto-exits when all Matrix windows close
- No crash recovery watchdog — if Matrix windows exist and service crashes, restart it
- No graceful shutdown handling — let Windows kill it
- No tray icon — completely invisible background process
- User stops via Task Manager if needed

### Feedback Behavior
- Silent operation for normal hotkey presses — the effect itself is feedback
- No audio feedback for v1.0 (custom Matrix sound deferred to v2)
- Silent failures — if action can't complete, do nothing
- No logging — no debug files

### Conflict Handling
- Attempt to register default hotkeys on startup
- If registration fails: show Windows Toast notification listing failed hotkeys
- Toast directs user to configure alternatives in Redpill
- Redpill gets new hotkey config screen (inside existing TUI, not separate app)
- Config screen checks availability on assign attempt (not real-time scanning)
- Shows X mark / rejection when user picks already-taken key
- Prevents invalid selections like Cubase does

### Hotkey Customization
- Full customization: user can change both modifier keys AND main key
- Users can disable individual hotkeys entirely (not just remap)
- "Reset to defaults" button available
- Config stored somewhere (Claude's discretion: JSON file vs registry)
- Default modifier combo: RESEARCH NEEDED — Win+Alt didn't work in PowerShell
- Researcher should investigate which modifiers have fewest conflicts with main keys

### Hotkey-able Actions (expanded from original 6)
1. Swap focused window with left neighbor
2. Swap focused window with right neighbor
3. Cycle layout mode (Pillars ↔ Quads)
4. Toggle background transparency
5. Decrease opacity (5% step, already in code)
6. Increase opacity (5% step, already in code)
7. Cycle through shader library
8. Adjust rain speed (up)
9. Adjust rain speed (down)
10. Toggle FAR layer
11. Toggle MID layer
12. Toggle NEAR layer

### Claude's Discretion
- Config file format and location (JSON vs registry)
- Whether to show known conflicting apps in config UI
- Technical approach for single-instance detection
- Message pump / hidden window implementation
- How to detect "Matrix windows exist" for auto-exit

</decisions>
