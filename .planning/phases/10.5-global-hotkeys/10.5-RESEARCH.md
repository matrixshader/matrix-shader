# Phase 10.5: Global Hotkeys - Research

**Researched:** 2026-01-30
**Domain:** Windows Global Hotkeys, P/Invoke, Message Pump, Single-Instance Patterns
**Confidence:** HIGH

## Summary

This phase ports `matrix_hotkeys.ps1` to C# -- system-wide keyboard shortcuts that work when Matrix windows are minimized. The PowerShell version uses a hidden WinForms Form with `RegisterHotKey` P/Invoke, and this pattern ports cleanly to C#. Research confirms:

1. **Modifier combination recommendation:** Use `Ctrl+Shift` (not `Win+Alt`) -- Win+Alt is reserved by Xbox Game Bar for screen recording (Win+Alt+R, Win+Alt+G, etc.), explaining why it "didn't work" in the PowerShell version.
2. **Hidden window pattern:** Required for RegisterHotKey -- create a message-only window or invisible window to receive WM_HOTKEY messages.
3. **Single-instance enforcement:** Named Mutex with GUID is the standard pattern; works perfectly with Native AOT.
4. **Toast notifications:** Use `Microsoft.Toolkit.Uwp.Notifications` package -- requires TFM `net8.0-windows10.0.17763.0` but is well-documented for console apps.

**Primary recommendation:** Create a new `MatrixShader.Hotkeys` project as a windowless background process that uses pure P/Invoke for the message pump (avoiding WinForms dependency for AOT compatibility).

### Pattern 1: Hidden Window for RegisterHotKey
**What:** RegisterHotKey requires a window handle (HWND) to receive WM_HOTKEY messages.
**When to use:** Always -- this is the Windows API requirement.
**Example:**
```csharp
// Source: Microsoft Learn RegisterHotKey documentation
public static partial class HotkeyApi
{
    private const int WM_HOTKEY = 0x0312;
    private static readonly nint HWND_MESSAGE = new(-3); // Message-only window

    [LibraryImport("user32.dll", SetLastError = true)]
    [return: MarshalAs(UnmanagedType.Bool)]
    public static partial bool RegisterHotKey(
        nint hWnd,
        int id,
        uint fsModifiers,
        uint vk);

    [LibraryImport("user32.dll", SetLastError = true)]
    [return: MarshalAs(UnmanagedType.Bool)]
    public static partial bool UnregisterHotKey(nint hWnd, int id);

    // Modifier constants
    public const uint MOD_ALT = 0x0001;
    public const uint MOD_CONTROL = 0x0002;
    public const uint MOD_SHIFT = 0x0004;
    public const uint MOD_WIN = 0x0008;
    public const uint MOD_NOREPEAT = 0x4000;

    // Virtual key codes for Matrix hotkeys
    public const uint VK_LEFT = 0x25;
    public const uint VK_RIGHT = 0x27;
    public const uint VK_L = 0x4C;
    public const uint VK_B = 0x42;
    public const uint VK_J = 0x4A;
    public const uint VK_K = 0x4B;
}
```

### Pattern 2: Message Pump Without WinForms
**What:** Pure P/Invoke message loop for AOT compatibility.
**When to use:** Background process without visible UI.
**Example:**
```csharp
// Source: MSDN "Handling Messages in Console Apps" + Microsoft Win32 docs
public class HotkeyWindow : IDisposable
{
    private delegate nint WndProc(nint hWnd, uint msg, nint wParam, nint lParam);

    [LibraryImport("user32.dll", SetLastError = true)]
    [return: MarshalAs(UnmanagedType.Bool)]
    private static partial bool GetMessageW(out MSG lpMsg, nint hWnd, uint wMsgFilterMin, uint wMsgFilterMax);

    [LibraryImport("user32.dll")]
    private static partial nint DispatchMessageW(ref MSG lpMsg);

    [LibraryImport("user32.dll")]
    private static partial void PostQuitMessage(int nExitCode);

    [StructLayout(LayoutKind.Sequential)]
    private struct MSG
    {
        public nint hwnd;
        public uint message;
        public nint wParam;
        public nint lParam;
        public uint time;
        public int pt_x;
        public int pt_y;
    }

    public void RunMessageLoop()
    {
        while (GetMessageW(out var msg, nint.Zero, 0, 0))
        {
            DispatchMessageW(ref msg);
        }
    }

    public void Stop() => PostQuitMessage(0);
}
```

### Pattern 3: Single-Instance with Mutex
**What:** Prevent multiple instances using named kernel mutex.
**When to use:** Always on startup.
**Example:**
```csharp
// Source: .NET documentation, verified AOT-compatible
public static class SingleInstance
{
    private const string MutexName = "Global\\MatrixShader.Hotkeys.{8A9B1C2D-3E4F-5A6B-7C8D-9E0F1A2B3C4D}";
    private static Mutex? _mutex;

    public static bool TryAcquire()
    {
        _mutex = new Mutex(true, MutexName, out bool createdNew);
        if (!createdNew)
        {
            _mutex.Dispose();
            _mutex = null;
            return false; // Another instance is running
        }
        return true;
    }

    public static void Release()
    {
        _mutex?.ReleaseMutex();
        _mutex?.Dispose();
        _mutex = null;
    }
}
```

### Pattern 4: Toast Notification for Conflict Warning
**What:** Show Windows toast when hotkeys fail to register.
**When to use:** On startup if any RegisterHotKey call fails.
**Example:**
```csharp
// Source: Microsoft Learn "Send a local toast notification"
// Requires: net8.0-windows10.0.17763.0 TFM
using Microsoft.Toolkit.Uwp.Notifications;

public static class HotkeyNotifications
{
    public static void ShowConflictWarning(IEnumerable<string> failedHotkeys)
    {
        var hotkeyList = string.Join(", ", failedHotkeys);

        new ToastContentBuilder()
            .AddText("Matrix Hotkeys: Some shortcuts unavailable")
            .AddText($"Failed to register: {hotkeyList}")
            .AddText("Open Redpill to configure alternatives")
            .Show();
    }

    // Call on app exit for non-MSIX apps
    public static void Cleanup()
    {
        ToastNotificationManagerCompat.Uninstall();
    }
}
```

### Anti-Patterns to Avoid
- **Using Console.ReadKey() for message pump:** Does NOT receive WM_HOTKEY messages. Must use GetMessage loop.
- **Polling approach:** Do NOT poll keyboard state. RegisterHotKey is event-driven and efficient.
- **Hardcoding hotkeys without config:** Always allow user customization for conflict resolution.
- **Forgetting MOD_NOREPEAT:** Without this flag, holding a key spams WM_HOTKEY. Always include it.
- **Global mutex without GUID:** Risk of collision with other apps. Always use unique GUID in mutex name.

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Keyboard hook for hotkeys | Low-level WH_KEYBOARD_LL hook | RegisterHotKey API | Hook is invasive, requires more privileges, harder to debug |
| Cross-process messaging | Custom IPC protocol | Named Mutex + existing services | Complexity not justified for single-instance check |
| Toast notification | Raw WinRT COM interop | Microsoft.Toolkit.Uwp.Notifications | Handles AUMID, COM registration, cleanup automatically |
| Window enumeration | Custom EnumWindows wrapper | Existing IdentityService.FindMatrixWindows() | Already built, tested, handles edge cases |
| Config persistence | Custom file format | Extend existing ConfigService | Consistency, atomic writes, JSON source-gen |

**Key insight:** The existing `MatrixShader.Core` services (IdentityService, LayoutService, ConfigService, ShaderService) already implement most hotkey actions. The Hotkeys project is primarily a thin wrapper that translates hotkey presses to service method calls.

## Common Pitfalls

### Pitfall 1: Win+Alt Reserved by Xbox Game Bar
**What goes wrong:** RegisterHotKey fails silently or returns false for Win+Alt combinations.
**Why it happens:** Xbox Game Bar reserves Win+Alt+R (record), Win+Alt+G (record last 30s), Win+Alt+B (HDR toggle), etc. These are system-level hotkeys that block registration.
**How to avoid:** Use Ctrl+Shift as the default modifier instead of Win+Alt.
**Warning signs:** RegisterHotKey returns false, GetLastError returns 1409 (ERROR_HOTKEY_ALREADY_REGISTERED).

### Pitfall 2: Message Pump Thread Affinity
**What goes wrong:** Hotkeys stop working after some time, or never work.
**Why it happens:** RegisterHotKey binds to a specific thread. The message pump must run on the same thread. Mixing async/await can switch threads.
**How to avoid:** Keep entire hotkey lifecycle on a dedicated STA thread. Never use async in the message pump loop.
**Warning signs:** Sporadic hotkey failures, works initially then stops.

### Pitfall 3: Forgetting to Unregister on Exit
**What goes wrong:** Hotkeys remain registered after app crashes, preventing next launch from registering them.
**Why it happens:** UnregisterHotKey not called on abnormal termination.
**How to avoid:** Windows automatically cleans up when process terminates. But for graceful shutdown, explicitly unregister. Use try-finally or AppDomain.ProcessExit.
**Warning signs:** "Hotkey already registered" on restart after crash.

### Pitfall 4: Toast Notifications Require AUMID
**What goes wrong:** Toast notifications don't appear or show generic app name.
**Why it happens:** Non-packaged apps need an Application User Model ID (AUMID) for toast attribution.
**How to avoid:** The Microsoft.Toolkit.Uwp.Notifications library handles this automatically with ToastNotificationManagerCompat.
**Warning signs:** Toasts show as "Windows Powershell" or don't appear at all.

### Pitfall 5: Mutex Name Without Global Prefix
**What goes wrong:** Single-instance check fails across different user sessions.
**Why it happens:** Without "Global\" prefix, mutex is per-session.
**How to avoid:** Always use "Global\\" prefix in mutex name.
**Warning signs:** Multiple instances can run if started from different user sessions.

### Pitfall 6: NativeAOT Trimming Removes P/Invoke
**What goes wrong:** App builds but crashes at runtime with missing method exceptions.
**Why it happens:** Trimmer removes unused code, including P/Invoke methods not detected statically.
**How to avoid:** Use `LibraryImport` source generator (not DllImport). It generates AOT-compatible code.
**Warning signs:** Trimming warnings during publish, runtime MissingMethodException.

## Code Examples

Verified patterns from official sources:

### Complete Hotkey Registration with Error Handling
```csharp
// Source: Microsoft Learn + verified against existing matrix_hotkeys.ps1
public class HotkeyManager : IDisposable
{
    private readonly nint _windowHandle;
    private readonly Dictionary<int, HotkeyBinding> _registeredHotkeys = new();
    private readonly List<string> _failedHotkeys = new();

    public bool RegisterHotkey(int id, uint modifiers, uint vk, string description, Action handler)
    {
        // Always include MOD_NOREPEAT to prevent auto-repeat spam
        uint mods = modifiers | HotkeyApi.MOD_NOREPEAT;

        if (HotkeyApi.RegisterHotKey(_windowHandle, id, mods, vk))
        {
            _registeredHotkeys[id] = new HotkeyBinding(description, handler);
            return true;
        }
        else
        {
            // GetLastError 1409 = ERROR_HOTKEY_ALREADY_REGISTERED
            _failedHotkeys.Add(description);
            return false;
        }
    }

    public void UnregisterAll()
    {
        foreach (var id in _registeredHotkeys.Keys)
        {
            HotkeyApi.UnregisterHotKey(_windowHandle, id);
        }
        _registeredHotkeys.Clear();
    }

    public IReadOnlyList<string> GetFailedHotkeys() => _failedHotkeys;

    public void HandleHotkey(int id)
    {
        if (_registeredHotkeys.TryGetValue(id, out var binding))
        {
            binding.Handler();
        }
    }

    public void Dispose() => UnregisterAll();

    private record HotkeyBinding(string Description, Action Handler);
}
```

## Modifier Key Analysis

### Win+Alt (Original PowerShell choice) - NOT RECOMMENDED
| Hotkey | Conflict | Application |
|--------|----------|-------------|
| Win+Alt+R | RESERVED | Xbox Game Bar - Start/Stop recording |
| Win+Alt+G | RESERVED | Xbox Game Bar - Record last 30 seconds |
| Win+Alt+B | RESERVED | Xbox Game Bar - HDR on/off |
| Win+Alt+PrtSc | RESERVED | Xbox Game Bar - Take screenshot |
| Win+Alt+T | RESERVED | Xbox Game Bar - Show/hide recording timer |
| Win+Alt+M | RESERVED | Xbox Game Bar - Toggle microphone |

**Verdict:** Win+Alt combinations are heavily used by Xbox Game Bar. This explains why matrix_hotkeys.ps1 had issues. Avoid.

### Ctrl+Shift - RECOMMENDED
| Hotkey | Potential Conflict | Risk Level |
|--------|-------------------|------------|
| Ctrl+Shift+L | VS Code: Select all occurrences | LOW - only in editors |
| Ctrl+Shift+J | Chrome: Downloads / VS Code: Join lines | LOW - app-specific |
| Ctrl+Shift+K | Edge/Chrome: Duplicate tab | MEDIUM - browsers |
| Ctrl+Shift+B | Chrome: Bookmarks bar | LOW - toggle only |
| Ctrl+Shift+Left/Right | Text selection | MEDIUM - text apps |

**Verdict:** Some conflicts exist but they're app-specific (only active when that app is focused). Global hotkeys take precedence. Most conflicts are in development tools, not typical Matrix shader usage. Good choice.

### Ctrl+Alt - ALTERNATIVE
| Hotkey | Conflict | Risk Level |
|--------|----------|------------|
| Ctrl+Alt+* | AltGr key produces Ctrl+Alt | HIGH on international keyboards |
| Ctrl+Alt+Del | RESERVED | System - Lock screen |
| Ctrl+Alt+Arrow | Intel Graphics rotation (legacy) | LOW - often disabled |

**Verdict:** AltGr issue makes this problematic for international users. Avoid.

### Final Recommendation: Ctrl+Shift with Fallback
1. Default to Ctrl+Shift combinations
2. Allow full customization of both modifier and key
3. Check availability on registration attempt
4. Show toast notification if conflicts found
5. Let users configure alternatives in Redpill

## Open Questions

Things that couldn't be fully resolved:

1. **Toast notification NativeAOT compatibility**
   - What we know: Microsoft.Toolkit.Uwp.Notifications uses COM interop internally
   - What's unclear: Whether all code paths are AOT-trimming safe
   - Recommendation: Test with PublishAot, suppress warnings if necessary, or fall back to no notification

2. **Ctrl+Shift+K browser conflict severity**
   - What we know: Chrome/Edge use this for "Duplicate tab"
   - What's unclear: Whether global hotkey blocks the browser shortcut entirely
   - Recommendation: Include in default set but document in user-facing help; users can remap if needed

3. **Message pump power consumption**
   - What we know: GetMessage blocks efficiently (no busy-wait)
   - What's unclear: Exact CPU/power impact of background process
   - Recommendation: Profile in real usage; expect negligible impact based on API design
