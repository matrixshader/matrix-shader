    Read the Windows implementation: `git show 8a296f6` for Construct/Program.cs white room + quick launch logic.

    **construct.sh** (new file `linux/construct.sh`):
    - Follow self-relaunch pattern from wakeupneo.sh exactly
    - Parse flags: `--green`, `--red`, `--blue`, `--purple`, `--gold`, `--teal` for standard colors
    - Parse flags: `--aurora`, `--aurora-rain`, `--fireplace`, `--codevision`, `--ultra`, `--rain-on-glass` for bonus shaders
    - Parse flags: `--pick` (inner invocation for white room), `--help`/`-h`
    - Standard paths: SCRIPT_PATH, PYMOD_DIR, SHADER_DIR, GHOSTTY_BIN, CONFIG_DIR (same pattern as wakeupneo.sh)

    Quick launch flow (any color/bonus flag):
    1. Call `python3 -B "$PYMOD_DIR/construct_service.py" quick-launch --color "$COLOR"` which:
       - Finds next available slot via process scanning
       - Creates the shader file (create_slot_shader for standard colors, file copy for bonus shaders)
       - Writes Ghostty config to /tmp/ghostty-matrix-{slot}.conf
       - Prints the slot number and config path to stdout
    2. Shell launches Ghostty: `nohup "$GHOSTTY_BIN" --config-default-files=false --config-file="$conf" >/dev/null 2>&1 &`
    3. Print confirmation and call `show_command_banner` via Python
    4. Exit 0

    White room flow (no args):
    1. Self-relaunch inside Ghostty with `--pick` flag and white-room shader as custom-shader
    2. Inner invocation (`--pick`):
       - Call `python3 -B "$PYMOD_DIR/construct_service.py" white-room` which:
         - Displays the arrow-key color picker via stdin/stdout (reuse arrow_menu pattern but in Python)
         - On selection, calls transition_to_rain() to swap shader in-place
       - After Python exits, the Ghostty window continues showing rain shader

    Help output (`--help`):
    ```
    Matrix Shader - Construct

    Usage: construct [--color]

    Colors:
      --green, --red, --blue, --purple, --gold, --teal

    Bonus Shaders:
      --aurora, --aurora-rain, --fireplace
      --codevision, --ultra, --rain-on-glass

    No arguments: opens the white room color picker
    ```
    Then show_command_banner.

    **construct_service.py** (new file `linux/construct_service.py`):
    - `find_next_slot() -> int | None`: scan running Ghostty processes, return lowest unused 1-8
    - `quick_launch(color: str) -> dict`: create shader, write config, return {"slot": N, "conf": path}
    - `transition_to_rain(slot: int, preset_idx: int)`: rewrite config from white-room to rain shader, update opacity, reload via D-Bus
    - `white_room_picker()`: arrow-key color picker loop (reads from /dev/tty, prints ANSI menu), returns selected preset index
    - Color name -> preset index mapping dict
    - Bonus shader name -> filename mapping dict
    - CLI entry point: `python3 construct_service.py quick-launch --color green` and `python3 construct_service.py white-room`

    For bonus shaders in quick_launch: copy the bonus .glsl file to the slot directory as `matrix-{slot}.glsl` (per RESEARCH.md Pitfall 6), then write a standard Ghostty config pointing to it. Do NOT use create_slot_shader (bonus shaders don't have #define parameters).

    **construct_service.py TransitionToRain details**:
    1. Create rain shader for the slot via `create_slot_shader(slot, preset_idx=idx)`
    2. Read current Ghostty config at `/tmp/ghostty-matrix-{slot}.conf`
    3. Replace `custom-shader = .../white-room.glsl` with `custom-shader = .../matrix-{slot}.glsl`
    4. Replace `background-opacity = 1.0` with `background-opacity = 0.85`
    5. Write config back via atomic write
    6. Call `reload_ghostty()` via D-Bus to trigger shader swap in the same window

    **Tests** (`linux/tests/test_construct.py`):
    - Mock shader_service calls and file I/O
    - Test find_next_slot with various occupied slot combinations
    - Test quick_launch for standard and bonus colors
    - Test transition_to_rain config rewrite logic
    - Test color and bonus shader name mappings
