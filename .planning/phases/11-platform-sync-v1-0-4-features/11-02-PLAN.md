       ```python
       _overflow_counters = {}   # config_path -> int
       ```

    - Test: redpill TUI window (ghostty-redpill config) not in tab list
    - Test: regular Ghostty windows (no matrix config) not in tab list
    - Test: only ghostty-matrix-{slot} config windows appear as tabs
  </behavior>
  <action>
    Read the Windows implementation: `git show caf095e -- MatrixShader/Core/TabManager.cs` to understand the filter criteria.

    The Linux implementation is simpler because `get_ghostty_bus_names()` in `shader_service.py` already filters by `/proc/{pid}/cmdline` matching `ghostty-matrix-{slot}`. This naturally excludes:
    - Regular Ghostty windows (no matrix config in cmdline)
    - Construct white room windows (config is `ghostty-construct.conf`, not `ghostty-matrix-{slot}.conf`)
    - Redpill TUI windows (config is `ghostty-redpill.conf`)

    So the primary work is:
    1. Verify that `redpill_tui.py`'s tab discovery (`_refresh_tabs` or equivalent method) uses `get_ghostty_bus_names()` and does NOT have any fallback path that could include non-shader windows.
    2. Read `redpill_tui.py` to find the tab discovery method. If there's any additional window discovery (like scanning /proc or D-Bus directly), add explicit filtering.
    3. Add a comment in the tab discovery method documenting that `get_ghostty_bus_names()` handles the filtering.

    Add test cases to `linux/tests/test_redpill_tui.py`:
    - Mock `get_ghostty_bus_names()` to return only matrix-slot windows
    - Verify that the TUI's tab list matches exactly what `get_ghostty_bus_names()` returns
    - Test that a mock mapping containing non-matrix entries (if manually injected) would be filtered
    - If no additional filtering is needed (existing code already correct), the tests serve as regression guards

    The key insight from the Windows port: Windows had a bug where `ShaderIndex == 0` windows (Construct, control panels) appeared in tabs and caused crashes. On Linux, the config-file pattern matching prevents this from ever happening, but we add tests to lock that behavior.
