The bug shows "Previous sessions found 8 window slots" on fresh install. This is impossible - there's no way for 8 slots to exist on a fresh system.

Investigation approach:
1. Find where "8 window slots" or "Previous sessions" message is generated
2. Trace back to find the source of the "8" value
3. Fix the root cause

Looking at WakeupNeo/Program.cs, the GetActiveSlots method:
```csharp
private List<int> GetActiveSlots(MatrixState state)
{
    if (state.ShaderConfigs == null || state.ShaderConfigs.Count == 0)
        return new List<int>();

    return state.ShaderConfigs.Keys
        .Where(k => _shaderService.ShaderExists(k))
        .OrderBy(k => k)
        .ToList();
}
```

This checks if ShaderConfigs exists AND if shader files exist. If both are empty, it returns empty list.

The issue might be in ConfigService.LoadState(). Let's check what happens when the state file doesn't exist.

Read ConfigService.cs to understand:
1. What file path is used for state?
2. What does LoadState return when file doesn't exist?
3. Is there a default value that creates 8 slots?

LIKELY ROOT CAUSE: The MatrixState object might have default values that include 8 slots, even when the file doesn't exist.

FIX APPROACH:
1. In ConfigService.LoadState(), return a truly empty state when file doesn't exist
2. Add explicit first-run check: ConfigService.IsFirstRun()
3. In WakeupNeo, use IsFirstRun() to skip "Previous sessions" message

Add to ConfigService (or create if not exists):

```csharp
/// <summary>
/// Checks if this is a first run (no state file exists).
/// </summary>
public bool IsFirstRun()
{
    var statePath = GetStatePath();
    return !File.Exists(statePath);
}

/// <summary>
/// Loads state from file. Returns empty state if file doesn't exist.
/// </summary>
public MatrixState LoadState()
{
    var statePath = GetStatePath();

    if (!File.Exists(statePath))
    {
        DiagnosticLogger.Debug("CONFIG", "No state file found - first run");
        return new MatrixState
        {
            ShaderConfigs = new Dictionary<int, ShaderConfig>(),
            WindowSlots = new Dictionary<int, WindowSlot>(),
            Layout = new LayoutConfig()
        };
    }

    try
    {
        var json = File.ReadAllText(statePath);
        var state = JsonSerializer.Deserialize<MatrixState>(json, _jsonOptions);

        // Ensure null collections become empty
        if (state != null)
        {
            state = state with
            {
                ShaderConfigs = state.ShaderConfigs ?? new Dictionary<int, ShaderConfig>(),
                WindowSlots = state.WindowSlots ?? new Dictionary<int, WindowSlot>()
            };
        }

        return state ?? new MatrixState();
    }
    catch (Exception ex)
    {
        DiagnosticLogger.Warn("CONFIG", $"Failed to load state: {ex.Message}");
        return new MatrixState();
    }
}
```

And in WakeupNeo SetupWizard.RunAsync(), add explicit first-run check:

```csharp
// Check for previous session
var state = _configService.LoadState();
var previousSlots = GetActiveSlots(state);

// Only show "Previous session found" if:
// 1. We have slots in state
// 2. The corresponding shader files actually exist
// 3. This is NOT a first run
if (previousSlots.Count > 0 && !_configService.IsFirstRun())
{
    ConsoleHelper.WriteMatrixGreen(" Previous session found:");
    // ... rest of previous session handling
}
```

Actually, the real issue might be in how _shaderService.ShaderExists() works. If it checks a default location that has bundled shaders, it would find them even on fresh install.

Let me trace ShaderExists():
1. It uses _shadersPath from constructor
2. Default path comes from GetDefaultShadersPath()
3. GetDefaultShadersPath() checks LocalAppData, Program Files, AppContext.BaseDirectory

On fresh install:
- LocalAppData\MatrixShader\shaders - EMPTY (doesn't exist yet)
- Program Files\MatrixShader\shaders - HAS shaders from installer!

So the issue is: the installer puts shaders in Program Files, and ShaderExists checks there, finding 8 shaders even though user never created them.

FIX: GetActiveSlots should only return slots that have BOTH:
1. A ShaderConfig in the state file
2. A shader file in the USER's shaders directory (not Program Files)

Or simpler: IsFirstRun should check if state FILE exists, not just if state has data.
